# Tiny Chatbot UltraChat Subword v2 Fixed Run

Date recorded: 2026-05-15

## Purpose

This run was the first corrected GPU training run after the `v1` UltraChat
candidate. It was intended to test whether the same `8x512` GPT-2 style model
and tokenizer would improve with twice the training text exposure while keeping
the experiment comparable.

## Code State Used

Important changes made before and during this stage:

- Added stop-controlled decoding defaults for chat:
  - `<END_ASSISTANT>`
  - `<CHAT_END>`
  - `\nUser:`
  - `\nAssistant:`
  - `\nSystem:`
- Added `tools/run_tiny_chatbot_ultrachat_decoding_eval.jl` for no-retraining
  decoding comparisons.

  - `--device auto|cpu|gpu`

  - retained latest two step checkpoints and latest two epoch checkpoints
  - stop-controlled future sample generation

  arrays.
- Fixed GPU cross entropy training by adding a custom ChainRules pullback for
  `causal_lm_cross_entropy`. Before this fix, GPU training reported invalid
  `recent_train_loss=-0.0000`.

Verification before the final run:

- A small script-entrypoint GPU run completed with `resolved_device: gpu`.
- A direct GPU loss check matched the expected CPU value.
- `Flux.withgradient` returned the same nonzero GPU loss as the direct forward
  loss.
- A full-shape GPU train step for the `8x512`, context `128`, batch `16` model
  returned a real nonzero loss.

## Training Command

The final corrected run used the 32GB RTX 5000 Ada GPU by UUID:

```bash
CUDA_VISIBLE_DEVICES=GPU-10d1f16f-9e79-08bb-b2ba-3353c04422cf julia --project=tools/subword_real_text tools/run_tiny_chatbot_ultrachat_subword_v1.jl --dataset-dir tmp/tiny_chatbot_ultrachat_corpus_v1 --output-dir tmp/tiny_chatbot_ultrachat_subword_candidate_run_v2_fixed --device gpu --context-length 128 --num-layers 8 --num-heads 8 --embedding-size 512 --ffn-hidden-size 2048 --batch-size 16 --epochs 2 --learning-rate 0.0003 --reuse-tokenizer-bundle-dir tmp/tiny_chatbot_ultrachat_subword_candidate_run_v1/tokenizer_bundle --train-text-limit 100000 --validation-text-limit 1000 --test-text-limit 1000 --checkpoint-every-steps 5000 --max-step-checkpoints 2 --max-epoch-checkpoints 2
```

## Training Recipe

- Dataset: `tmp/tiny_chatbot_ultrachat_corpus_v1`
- Source corpus: `HuggingFaceH4/ultrachat_200k`, SFT splits, filtered and
  normalized into explicit `User:` / `Assistant:` turns.
- Tokenizer: reused `v1` `KeemenaSubwords.jl` GPT-2 byte-BPE tokenizer.
- Vocab size: `8192`
- Context length: `128`
- Model:
  - layers: `8`
  - heads: `8`
  - embedding size: `512`
  - FFN hidden size: `2048`
- Backend: Flux
- Device: GPU
- Optimizer: `Flux.Adam(0.0003)`
- Batch size: `16`
- Epochs: `2`
- Training text limit: `100000`
- Validation text limit: `1000`
- Test text limit: `1000`
- Train batches per epoch: `55642`
- Final step: `111284`

## Results

Final metrics:

- Epoch 2 train loss: `2.771995539587409`
- Validation loss: `2.6447167355808423`
- Test loss: `2.668845098776673`

Comparison to the prior `v1` candidate:

- `v1` validation loss: about `2.9413`
- `v2_fixed` validation loss: `2.6447`
- `v1` test loss: about `3.0498`
- `v2_fixed` test loss: `2.6688`

This is a material numeric improvement over `v1`.

## Qualitative Result

The model is still not a good chatbot.

Observed in generated samples and interactive chat:

- wrong-task drift remains common
- repeated list items and repeated phrases remain common
- answers sometimes continue into fake extra turns
- responses can start plausibly but then loop or move off-topic

The run proves that the Julia training/export/load path works and improves with
more data exposure, but it does not yet demonstrate a strong working chatbot.

## Next Recommendation

Do not spend another multi-day run simply repeating this exact setup. The next
work should target chatbot quality directly.

Implemented after this run:

- assistant-only supervised chat loss is now the runner default
- all-token LM loss is still available with `--loss-mode all_tokens`
- the next recommended run should use `--loss-mode assistant_only`

Remaining next work:

- add repetition controls if they can be implemented cleanly
- improve corpus filtering toward short direct assistant answers
- consider longer context or larger model only after reducing wrong-task drift
  and repetition in the data/evaluation path
